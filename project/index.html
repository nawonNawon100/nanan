01 · 해결한 문제

알면서도 "그냥 하던 대로"

가상 사용자 한도윤(3개월 차 신입 주무관)을 인터뷰했어요. 도윤 씨는 적극행정이 무엇인지 알고 있었지만, 틀릴까 봐 불안하고 선배에게 계속 묻기는 눈치가 보여서 결국 하던 대로 일하고 있었어요.

"신입이 '적극적으로' 하다가 틀리면 어쩌나 싶어서… 그냥 하던 대로 하게 되더라고요" — 가상 인터뷰, 한도윤

어떻게 하면 (HMW)

어떻게 하면 도윤 씨가 민원 응대 중 최신 안내를 한눈에 확인해서, 틀릴 걱정 없이 적극행정을 할 수 있을까?

전공(행정학) 연결 — 일선관료가 불확실성 속에서 만든 비공식 루틴("하던 대로", 개인 메모)을 절차에 맞는 점검 루틴으로 바꾸는 것이 목표였어요.

03 · 만든 과정

디자인씽킹으로 기획하고, 단계별로 만들었어요

  1. 직무에서 출발

    희망 직무를 웹·서비스 기획자로 정하고, 증명할 역량으로 화면 설계(UI)와 사용자 경험(UX) 설계를 골랐어요.

  2. 가상 사용자 인터뷰 → 공감지도

    AI가 연기한 신입 주무관에게 질문 5개를 하고, 말·생각·행동·느낌을 정리했어요. "뭐가 최신인지 몰라서 몇 개를 다 열어 봐요"가 핵심 불편이었어요.

  3. 문제 정의 + AI 검수

    관점 문장(POV)과 HMW를 만들고 7가지 기준으로 검수했어요. "적극행정"을 핵심 키워드로 넣어 한 번 보완했어요.

  4. 아이디어 5개 중 선택

    카드 보드, SOP 노트, 창구 모드 등 5개 중 적극행정 신호등을 골랐어요. 신입이 혼자서 절차에 맞게 판단할 수 있기 때문이에요.

  5. 기능을 고르며 내린 결정

    • 입력은 글쓰기로 — 구체적인 상황을 파악해야 판단할 수 있어서
    • 창구 모드 대신 유형 카드 — 이 앱은 민원인이 아닌 공무원용이라서
    • 민원인 정보는 연습용 + 가림 — 개인정보는 최소로, 화면에서는 가려서
    • 법령 검색은 링크로 — 화면(UI)에 집중하기 위해

  6. PRD → 7단계 개발 → 검수

    PRD(개발 설계서)를 쓰고, 화면 뼈대 → 샘플 데이터 → 점검 → 결과 → 저장 순서로 만들었어요. 신호등 색과 문구가 어긋난 문제를 직접 찾아 고쳤어요.
